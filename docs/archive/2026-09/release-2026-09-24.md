## Frontend fix: Maps key missing (redeployed)

**Found by the owner:** the maps said "Google Maps API key is missing."

**Cause:** the Client's `wwwroot/appsettings.json`, which holds the
browser Maps key, is ignored by git. The clean worktree used for the
frontend release lacked it, so `release-STi0MO` shipped without it, and
Hosting answered `/appsettings.json` with the entry HTML. Nothing in the
gate checked for it. The earlier artifact `release-vmWRzF`, built from the
main tree, had it.

**Fix, owner-approved:**
- The local file was copied into the same clean worktree of `90cae9aa`,
  and `bash deploy-client.sh` ran again.
- The gate passed (Server 3,607, Client C# 1,114, JavaScript 635) and
  verified `release-4Fvz7e`. Firebase answered "release complete".

**Checked afterwards:**
- `/appsettings.json` is served as `application/json`, `no-cache`, and is
  byte-identical to the local file (compared, not printed);
- `main.css?v=7655363164c59087` is unchanged, so the code is the same;
- on `amftms.web.app`, the Maps script loaded with the served key and
  logged no errors;
- not checked: a signed-in map in production.

**Guard, local:** `5049db24` makes `deploy-client.sh` refuse an artifact
that leaves any setting of `appsettings.example.json` empty. It refuses
`release-STi0MO` and accepts `release-vmWRzF`.

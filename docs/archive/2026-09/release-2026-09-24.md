## Follow-up patch, not deployed: WhatsApp credentials

Found by the owner after this release: the WhatsApp settings card refuses
every save. It has four fields, and the command capped every provider at
three (`fields.Count > 3`), counted by key even when blank. Fixed locally
in `8abba08b`: the cap comes from the provider's catalogued fields. There
are regressions on the server and Client sides.

This affects saving, not sending. No credential was saved and no message
was sent.

**To release it:**
- **Change:** a server-only validation change. It needs no migration and no
  frontend deploy (the Client changed only in tests). The deployed
  frontend already sends the four fields.
- **Gate:** the full gate on the final tree that contains it
  (`bash test.sh all`, then `PULSARTMS_RELEASE_UI=1 bash
  verify-release.sh`), with nothing changed in the tree while it runs.
- **Deploy:** `bash deploy-server.sh` from a clean worktree of that commit,
  then the same revision, traffic, drain, health and protected-data
  checks as above.
- **Afterwards:** saving WhatsApp credentials needs all four together. The
  app secret is required: webhook signatures are checked with it, so a save
  without it cannot receive messages. This is the owner's step and was not
  done here.
